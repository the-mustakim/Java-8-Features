## **I. Introduction & Rationale for New API**

The Java 8 Date & Time API (JSR-310) was introduced to overcome significant limitations of the older java.util.Date and java.util.Calendar classes. The primary issues with the legacy APIs were:

- **Mutability:** Old Date and Calendar objects were mutable, meaning their values could be changed after creation. This led to potential "extra tension" and made them "not thread-safe," increasing the chances of bugs, especially in multi-threaded environments. As the source states: "The first issue was that the dates or times created from them were mutable, meaning you could change a created Date object. Now, why is this an issue? When an object is mutable, unnecessary tension increases. For example, we know that String is immutable, so we don't have to worry about anything; our String will remain as it is." The new API resolves this by providing immutable date and time objects, ensuring "consistency will be maintained" and they will be "thread-safe, due to which chances of bugs will be less."
- **Confusing Design:** The older APIs were "very confusing" and lacked a "consistent design." The new API, in contrast, boasts a "quite good design" and is "easy to understand."
- **Limited Functionality:** Legacy classes offered "limited functionality" especially "when it comes to zones" and "when we talk about time difference, their condition would worsen." The new API provides robust support for time zones and calculating time differences.

## II. Core Classes Introduced in Java 8 Date & Time API

The new API introduces several key classes within the java.time package (replacing java.util for date/time operations), each designed for specific purposes:

1. **LocalDate**: Represents a date **without a time-zone**.
    - **Creation:**LocalDate.now(): Returns the current system date.
    - LocalDate.of(year, month, dayOfMonth): Creates a custom date, e.g., LocalDate.of(1990, 2, 7).
    - **Manipulation:**getYear(), getMonth(), getDayOfMonth(), getMonthValue(): Retrieve specific parts of the date.
    - minusDays(), minusMonths(), minusWeeks(), minusYears(): Subtract from the date. The source demonstrates: today.minusDays(1) for yesterday, and today.minusMonths(100) for a past date.
    - plusDays(), plusMonths(), etc.: Add to the date.
    - **Comparison:** isAfter(otherDate): Checks if the current date is after another.
    - isBefore(otherDate): Checks if the current date is before another.
    
    ```java
    package DateAPI;
    
    import java.time.Month;
    import java.time.LocalDate;
    
    public class _LocalDate {
        public static void main(String[] args) {
    
            LocalDate now = java.time.LocalDate.now();
            System.out.println( "Today's date: " + now);
    
            LocalDate of = java.time.LocalDate.of(2000, 12, 11);
            System.out.println("Mustakim DOB:" + of);
    
            int dayOfMonth = of.getDayOfMonth();
            Month monthName = of.getMonth();
            int month = of.getMonthValue();
            int year = of.getYear();
    
            System.out.println("Mustakim DOB:" + dayOfMonth + "/" + monthName + "{"+month+"}" + "/" + year);
    
            LocalDate today = java.time.LocalDate.now();
            System.out.println("Aj ki date: " + today);
    
            LocalDate yesterday = today.minusDays(1);
            System.out.println("Kal jo guzra uski date:" + yesterday);
    
            today.minusMonths(100);
            System.out.println("100 mahine purani date:" + today);
    
            if(today.isAfter(yesterday)){
                System.out.println("haa bhai");
            }
    
        }
    }
    
    ```
    
2. **LocalTime**: Represents a time **without a time-zone**.
    - **Creation:**LocalTime.now(): Returns the current system time (including nanoseconds).
    - LocalTime.of(hour, minute, second, nanoOfSecond): Creates a custom time, e.g., LocalTime.of(2, 30, 30).
    - **Manipulation:**getHour(), getMinute(), getSecond(), getNano(): Retrieve specific parts of the time.
    - minusHours(), minusMinutes(), minusSeconds(), minusNanos(): Subtract from the time.
    - **Parsing:**LocalTime.parse("HH:MM:SS"): Converts a string representation of time into a LocalTime object.
    - **Comparison:**isAfter(otherTime), isBefore(otherTime).
    
    ```java
    package DateAPI;
    
    import java.time.LocalTime;
    
    public class _LocalTime {
        public static void main(String[] args) {
    
            LocalTime now = LocalTime.now();
    
            LocalTime customTime1 = LocalTime.of(14,30,24);
    
            LocalTime customTime2 = LocalTime.of(14,32);
    
            String timeParse = "15:29:10";
            LocalTime parsedTime = LocalTime.parse(timeParse);
            System.out.println(parsedTime);
            LocalTime beforeTime = now.minusHours(1);
            System.out.println("Ek ghante pahle kya time tha?: " + beforeTime);
    
            if(now.isAfter(beforeTime)){
                System.out.println("Ha bhai badmai ata hai");
            }
        }
    
    }
    
    ```
    
3. **LocalDateTime**: A combination of LocalDate and LocalTime, representing date and time **without a time-zone**.
    - **Creation:**LocalDateTime.now(): Returns the current system date and time.
    - LocalDateTime.of(year, month, dayOfMonth, hour, minute, second, nanoOfSecond): Creates a custom date-time.
    - **Parsing:**LocalDateTime.parse("YYYY-MM-DDTHH:MM:SS"): Converts a string representation into LocalDateTime. The source notes the T is a separator between date and time.
    - Supports similar manipulation and comparison methods as LocalDate and LocalTime.
    
    ```java
    package DateAPI;
    
    import java.time.LocalDateTime;
    
    public class _LocalDateTime {
        public static void main(String[] args) {
            LocalDateTime now = LocalDateTime.now();
            System.out.println(now);
    
            LocalDateTime myDate = LocalDateTime.parse("2023-01-15T10:14:05");
            System.out.println("MyDateTime: " + myDate);
    
        }
    }
    
    ```
    
4. **ZonedDateTime**: Represents a date and time **with a time-zone**. This addresses a key limitation of the old APIs.
    - **UTC (Universal Time Coordinated):** The source introduces UTC as a "standard time" that is "same everywhere in the world." All other time zones are relative to UTC (e.g., UTC+5:30 for Asia/Kolkata). There are "around 24 primary zones" globally.
    - **Creation:**ZonedDateTime.now(): Returns the current system date, time, and time zone. The output includes the offset from UTC (e.g., +05:30) and the ZoneId (e.g., Asia/Kolkata).
    - ZonedDateTime.of(year, month, dayOfMonth, hour, minute, second, nanoOfSecond, ZoneId): Creates a custom ZonedDateTime for a specific time zone.
    - **ZoneId**: Represents a time-zone identifier (e.g., ZoneId.of("America/New_York")).
    - ZoneId.getAvailableZoneIds(): Returns a set of all available zone IDs (can be over 600, with 24 primary ones).
    - **Usage:** Useful for handling times across different geographical regions, e.g., comparing time in India vs. New York.
    
    ```java
    package DateAPI;
    
    import java.time.LocalDateTime;
    import java.time.ZoneId;
    import java.time.ZonedDateTime;
    import java.time.format.DateTimeFormatter;
    import java.util.Set;
    
    public class _ZonedDateTime {
        public static void main(String[] args) {
            // 1) Current zoned datetime in system default zone
            ZonedDateTime now = ZonedDateTime.now();
            System.out.println("Default zone: " + now);
    
            // 2) Current zoned datetime for Europe/Dublin
            ZonedDateTime dublin = ZonedDateTime.now(ZoneId.of("Europe/Dublin"));
            System.out.println("Dublin time:  " + dublin);
    
            // 3) Convert an instant/time from one zone to another (keeps same instant)
            ZonedDateTime qatar = ZonedDateTime.now(ZoneId.of("Asia/Qatar"));
            ZonedDateTime qatarToDublin = qatar.withZoneSameInstant(ZoneId.of("Europe/Dublin"));
            System.out.println("Qatar now:         " + qatar);
            System.out.println("Same instant in Dublin: " + qatarToDublin);
    
            // 4) Create a ZonedDateTime from a LocalDateTime (interpret as local wall time)
            LocalDateTime local = LocalDateTime.of(2025, 10, 26, 1, 30); // ambiguous around DST
            ZonedDateTime zdtDublin = ZonedDateTime.of(local, ZoneId.of("Europe/Dublin"));
            System.out.println("Local interpreted in Dublin: " + zdtDublin);
    
            // 5) Format for display
            DateTimeFormatter fmt = DateTimeFormatter.ofPattern("dd/MM/yyyy HH:mm:ss O z");
            System.out.println("Formatted Dublin: " + fmt.format(zdtDublin));
    
        }
    }
    
    ```
    
5. **Instant**: Represents a point in time on the timeline in nanoseconds, primarily for machine processing. It's an improvement over System.currentTimeMillis().
    - **Concept:** Measures time from the "epoch" (January 1, 1970, 00:00:00 UTC).
    - **Creation:**Instant.now(): Returns the current instant.
    - **Output:** Includes date, time up to seconds, nanoseconds, and Z for UTC (e.g., 2023-04-24T02:40:00.613919300Z).
    - **Conversion:** Can be converted to ZonedDateTime using atZone(ZoneId).
    - Supports plus/minusNanos(), plus/minusMillis(), plus/minusSeconds().
    
    ```java
    package DateAPI;
    
    import java.time.Instant;
    import java.time.ZoneId;
    import java.time.ZonedDateTime;
    import java.time.format.DateTimeFormatter;
    
    public class _Instant {
        public static void main(String[] args) {
            // 1) Millis -> Instant
            long epochMillis = System.currentTimeMillis();
            Instant fromMillis = Instant.ofEpochMilli(epochMillis);
            System.out.println("epochMillis: " + epochMillis);
            System.out.println("fromMillis (Instant): " + fromMillis);
    
            // 2) Instant -> millis
            Instant now = Instant.now();
            long asMillis = now.toEpochMilli();
            System.out.println("now (Instant): " + now);
            System.out.println("now as millis: " + asMillis);
    
            // 3) Instant -> ZonedDateTime in system zone (useful for display)
            ZonedDateTime zdtSystem = now.atZone(ZoneId.systemDefault());
            System.out.println("ZonedDateTime (system): " + zdtSystem);
    
            // 4) Instant -> formatted string
            DateTimeFormatter fmt = DateTimeFormatter.ofPattern("dd/MM/yyyy HH:mm:ss")
                    .withZone(ZoneId.systemDefault());
            System.out.println("Formatted local time: " + fmt.format(now));
    
            // 5) Parse an ISO Instant string
            Instant parsed = Instant.parse("1998-04-25T10:15:30Z");
            System.out.println("parsed instant: " + parsed);
        }
    }
    
    ```
    
6. **Duration**: Measures a quantity of time in seconds and nanoseconds. It is "used when we play with seconds, minutes, hours."
    - **Creation:**Duration.between(startInstant, endInstant): Calculates the duration between two Instant objects.
    - Duration.of(amount, ChronoUnit): Creates a duration of a specific amount in a given unit (e.g., Duration.of(1, ChronoUnit.MILLIS)).
    - **Usage:** Ideal for measuring elapsed time for short periods, such as "if we need to calculate some difference," or a "subscription needs to be renewed after 30 days."
    - The source explicitly shows that Duration.between() on LocalDate objects (which lack time components) results in an error because it "doesn't consider the time factor."
    
    ```java
    package DateAPI;
    
    import java.time.Duration;
    import java.time.Instant;
    import java.time.temporal.ChronoUnit;
    
    public class _Duration {
        public static void main(String[] args) throws Exception{
    
            //Example 1:
    
            Instant start = Instant.now();
    
            // simulate work
            Thread.sleep(37); // 37 ms
    
            Instant end = Instant.now();
            Duration d = Duration.between(start, end);
    
            System.out.println(d);                  // e.g. PT0.037S
            System.out.println(d.toMillis() + " ms"); // e.g. 37 ms
            System.out.println(d.toNanos() + " ns");  // e.g. 37000000 ns
    
            System.out.println("--------------------------------------------------------------------------------");
    
            //Example 2:
    
            long start2 = System.nanoTime();
    
            // simulate work
            for (int i = 0; i < 1_000_000; i++) { Math.sqrt(i); }
    
            long end2 = System.nanoTime();
            long elapsedNanos = end2 - start2;
    
            System.out.println(elapsedNanos + " ns");
            System.out.printf("%.3f ms%n", elapsedNanos / 1_000_000.0);
    
        }
    }
    
    ```
    
7. **Period**: Measures a quantity of time in years, months, and days. It is used "when big dates come, days come, months come, years come."
    - **Creation:**Period.between(startDate, endDate): Calculates the period between two LocalDate objects.
    - **Output:** Provides human-readable output like "33 years 2 months 22 days."
    - **Usage:** Best for large time differences like age or subscription renewal on a monthly/yearly basis.
    - Supports plus/minusYears(), plus/minusMonths(), plus/minusDays().
    
    ```java
    package DateAPI;
    
    import java.time.LocalDate;
    import java.time.Period;
    
    public class _Period {
        public static void main(String[] args) {
            LocalDate now = LocalDate.now();                 // e.g. 2025-09-14
            LocalDate then = LocalDate.of(1990, 2, 2);      // 1990-02-02
    
            Period period = Period.between(then, now);      // earlier, later
            System.out.println(period);                     // e.g. P35Y7M12D
    
            // Friendly output:
            System.out.printf("%d years, %d months, %d days%n",
                    period.getYears(), period.getMonths(), period.getDays());
            // e.g. 35 years, 7 months, 12 days
    
        }
    }
    
    ```
    
8. **DateTimeFormatter**: Formats and parses dates and times. This is crucial for handling different date/time string representations.
    - **Problem:** Direct parse() methods in LocalDate, LocalTime, LocalDateTime, ZonedDateTime require a specific default format (e.g., YYYY-MM-DD for LocalDate). If the string doesn't match, an Exception is thrown.
    - **Solution:** DateTimeFormatter allows defining custom patterns.
    - DateTimeFormatter.ofPattern("dd/MM/yyyy"): Creates a formatter with a custom pattern.
    - **Formatting:** localDate.format(myFormatter): Converts a LocalDate object into a string with the specified format.
    - **Parsing:** LocalDate.parse(dateString, myFormatter): Converts a string with a custom format into a LocalDate object.
    - **Pattern Symbols (Important distinctions):**yyyy: Year
    - MM: Month (capital M for month, small m for minute)
    - dd: Day of month
    - HH: Hour (24-hour format)
    - mm: Minute
    - ss: Second
    - xx: Offset for time zones (e.g., +05:30). This is preferred over zzz (zone name) to avoid ambiguous mappings like "IST" which could mean "Indian Standard Time" or "Israel Standard Time."
    
    ```java
    package DateAPI;
    
    import java.time.LocalDate;
    import java.time.format.DateTimeFormatter;
    
    public class _DateTimeFormatter {
        public static void main(String[] args) {
    
            LocalDate localDate = LocalDate.now();
            // Use yyyy for year and MM for month
            DateTimeFormatter myFormatter = DateTimeFormatter.ofPattern("dd/MM/yyyy");
            String format = localDate.format(myFormatter);
            System.out.println(format); // e.g. 14/09/2025 (depends on current date)
    
            String date = "25/04/1998";
            // Use uppercase M for month
            DateTimeFormatter dateTimeFormatter = DateTimeFormatter.ofPattern("dd/MM/yyyy");
            LocalDate localDate2 = LocalDate.parse(date, dateTimeFormatter);
            System.out.println(localDate2); // prints 1998-04-25 (ISO format)
        }
    }
    
    ```
